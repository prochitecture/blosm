# Original parameters on prepared source curbs

Prepared source-strip and source-port polylines retain original parameters beside
their existing vertices. This supports source-labelled height conditions and
finite junction influence without identifying a bank from its XY proximity.
It is metadata; it adds no physical vertices, faces, source nodes or connectivity.

`CurbCoordinates` stores immutable arrays of exact source stations, lateral
offsets in metres, and declared bank sides. An original strip uses its actual
`Path`. An ordinary port also retains the exact original `Approach` and `Route`.
The right and left banks keep opposite order. Root caps retain their changing
side/offset and are not described as an entire constant bank. Existing duplicate
point removal and orientation changes carry explicit retained vertex indices.

One represented chord can cross a real compatible Route seam. `edge_sources()`
then returns finite `OriginalCurbPiece` intervals for the actual original Paths,
with a fraction of the existing chord, native station endpoints, authored
lateral offsets and the correctly oriented original bank side. Reversed
traversals reverse stations and offset signs. It does not insert a vertex at
the seam or claim that the existing straight chord becomes a new original Path.
The source parameters and the represented physical chord remain distinct.

`validate()` evaluates the declaration directly against the stored physical
vertices and optionally requires every native Path to be the context's actual
Path object. There is no closest-point search or inferred Section assignment.
A derived approach without this contract records explicit unavailable ancestry;
it receives no fabricated original parameter map. Height consumers must handle
that case explicitly before claiming source-height qualification.

The current policy is `6-explicit-owned-prefix-physical-native-ledgers`.
The exact `OwnedPrefixRoute` producer type can retain its physical external
Route's station map, actual native pieces and half-profile bank sides while its
logical Section remains a separate ownership/incidence witness. This does not
admit arbitrary Route subclasses. Current-group whole-prefix/final-mouth proof
precedes height-rule admission; see
[the owned-prefix contract](STREETS_OWNED_PREFIX_CORNER_AUTHORITY.md).

The original full-batch contract from policy 5 remains unchanged.
Native source builders explicitly supply their original monotone
`evaluation_grid`. The constructor independently evaluates both complete banks
on that grid, then derives an immutable reference for each declared source
vertex. Subsets retain the matching reference and exact station, offset and
side arrays. Validation compares the physical vertex bytes to that original
source evaluation and still requires the actual context Path identity.

This distinction matters because an array calculation on a shorter or reversed
batch can round differently by one floating-point ulp. Re-evaluating a split
strip with another batch shape can therefore reject a vertex that has never
moved. The explicit original batch resolves that provenance problem. It does
not accept an XY tolerance, arbitrary caller-provided reference points, changed
parameters or a nearby Path. Even a one-ulp change to the stored physical vertex
is rejected. References and their arrays are immutable. Legacy ledgers without
an original batch retain their strict direct-evaluation behavior and must be
regenerated by the maintained builders to gain the new declaration.

The parameter policy participates in the PLAN version and projected layout and
surface fingerprints, which otherwise omit the global PLAN digest. A cached
owner from before this metadata contract must be rebuilt normally.

## Coincident native banks

A finite dimensional continuation can retain an analytical `OffsetCurb` on an
original bank while an adjacent port retains a sampled polyline of that same
bank. Boolean clipping can alternate between the two approximations, producing
tiny A/B/A ownership islands. An ordinary curve-intersection solve is
inappropriate: the original analytical bank is coincident with itself.

`canonical_native_banks()` acts only at an exposed owner switch whose finite
contact neighborhoods identify the **same actual native Path object**, exactly
the same authored lateral bank offset, and overlapping original station ranges.
It uses declared parameter maps, including reversed Route pieces; it does not
merge nearby coordinates or unrelated roads. Other prepared curves retain their
piecewise linear evaluation.

For an eligible port, `NativeBankCurb` evaluates its existing parameter lattice
on the declared original bank. Every existing vertex remains compulsory and
byte-exact. Original Route seams and Exact path knots are compulsory semantic
cuts too. The original positive finite sampling tolerance is stored as the
read-only `CurbCoordinates.maximum_chord_error` property, supplied by the port
builder and retained by every subset. A legacy ledger without this declaration
cannot enable analytical replacement.

New sampling uses the smallest of the caller's tolerance, the declared original
source tolerance, and the curvature/speed bound of the old chord lattice. A
global curvature bound therefore cannot weaken a finer original construction
budget. Existing allocation limits still apply; the operation rejects an
unrepresentable knot or exhausted sample budget rather than dropping a cut.
Root caps and mixed-bank polylines cannot use this branch.

An `OffsetCurb` also retains every interior knot of its own cumulative-length
lookup as a compulsory sampling cut. The physical bank is unchanged, but its
piecewise inverse parameter map changes derivative there. Fitting one boundary
jet polynomial across an omitted lookup knot could exceed the existing fit
tolerance. Retaining the declared cuts resolves that parameter discontinuity;
it does not relax the fit or source-curve accuracy requirements.

The normal canonical ownership pass can then remove redundant same-bank islands
and select an exact common finite source station. Original area operands,
mouths, profiles, logical membership and ownership claims remain authoritative.
The usual boundary-topology, complete-source-width and later surface checks
still apply. This resolves representation of a coincident bank; it does not
round a genuine corner or prove compatibility of different boundary heights.

The maintained [tests](../tests/test_python_street_source_curb_coordinates.py)
cover Exact and smooth banks, reversal, curve/label/vertex parity, root caps,
explicit reversed Route seams, false parameter maps, original Path ownership,
invalid ranges and real coordinator invalidation. The initial five focused tests
pass, including exact geometry comparisons and real coordinator invalidation.
Complete city and source-height qualification remain separate requirements.

The [native-bank tests](../tests/test_python_street_native_curb_ownership.py)
add reversed analytical wrappers, same-coordinate different-Path rejection,
different offsets and disjoint domains, optional-branch isolation, compulsory
semantic knots, declared tolerances from 1 mm to 0.01 mm, malformed or legacy
ledgers, and unchanged resource limits. They complement the original metadata
and normal coordinator checks; they are not whole-city qualification.

## An original circle inside a prepared curve with auxiliary leads

A source fillet can have a negative auxiliary contact. Its prepared curb then
contains a circular arc and an existing bank lead in one curve. The complete
curve's normalized chord distance is not the circle's angular phase. A caller
must not infer a pure circle merely because the source Corner has a center.

`corner_patch()` retains the semantic arc phase during its actual append
operations. The tags follow existing duplicate handling, polygon orientation
and semantic curve grouping. It publishes `curve.original_circle_interval`, a
`PreparedCircularInterval` from
[`source_circular_intervals.py`](../way/street_network/python_backend/source_circular_intervals.py).
The policy is `1-original-prepared-circle-subintervals`. Region vertices,
segment labels, original corners and all prepared curve points are unchanged.

For each original arc vertex, the record retains the prepared parameter
`u_j = s_j / L` and the generating circle phase `q_j`. The explicit piecewise
maps are

```text
q(u) = interpolate(u; u_j, q_j)
u(q) = interpolate(q; q_j, u_j)
circle(u) = C + R (cos(a + sweep q(u)), sin(a + sweep q(u)))
```

`circle_parameter()` and `source_parameter()` implement those finite maps,
including reversed phase order. The record keeps exact original vertex indices
and coordinate references, the original Corner identity and the original chord
error budget. Validation checks both the declaration and the actual analytical
circle; it does not discover a circle by comparing radial distances. A legacy
curve without the declaration does not acquire inferred subinterval ancestry.

`PreparedAuxiliaryLead` separately records the existing original Approach,
bank side, prepared parameters, construction stations and original vertices.
Those auxiliary stations can be negative because they describe an already
constructed source fillet. They do not establish negative native Path ownership
or authorize a new extrapolated contact. Consumers keep the lead domain and
circle domain separate; contact, source-height and sampling rules must use the
explicit domain map.

The focused
[`test_python_street_source_circular_intervals.py`](../tests/test_python_street_source_circular_intervals.py)
tests positive, mixed and both-negative contacts, native and routed sources,
reversal, finite maps, identity/vertex changes and forged phases. An independent
comparison with the pre-metadata generator confirms byte-exact region vertices,
segment labels and prepared curves in twelve transformed cases. This metadata
parity does not qualify an unsupported intersection between a polynomial
continuation and another curb; that remains a separate geometry requirement.
